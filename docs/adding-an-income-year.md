# Adding an income year

Rates are data: each income year is one module in `src/tax/years/` (`2025.ts` is the template). Do the steps in order and record what each table was taken from in the module's `sources`. The method itself is described in [tax-model.md](tax-model.md).

1. **Collect official figures first.** Dutch Box 1 brackets, premium rate and ceiling, algemene heffingskorting and arbeidskorting tables (Belastingdienst) and, for Belgium, brackets, belastingvrije som with child supplements, the professional-expenses forfait, and the federal/regional rates (FOD Financiën; Belgian assessment year is the income year + 1). Do not interpolate from earlier years.
2. **Create `src/tax/years/<year>.ts`** by copying the latest module and replacing every figure. It calls `defineYear` with:
   - `nl`: `mortgageDeductionRateCap`, one shared `incomeTaxBrackets` list (income-tax-only rates: combined rate minus the premium rate), and `under` / `over` values for the algemene heffingskorting (`ahk*`) and arbeidskorting (`akStages`). The over-AOW brackets, the premium ceiling (the first bracket's `to`) and the premium rates (27.65% / 9.75%) are derived, so do not repeat them.
   - `be`: brackets, `baseBelastingvrijeSom`, `childExtraAmounts`, `extraPerChildAbove4` (a number, or `null` to limit the form to the children the table covers) and `forfaitMax`. `forfaitRate`, `gereduceerdRate`, `gewestelijkeRate` and `serviceVoucherReductionRate` default to the shared values in `src/tax/years/shared.ts`; set one in the module only if the law changed for that year.
   - `home`: the eigenwoningforfait `rates` (one per value band), `threshold` and `base`. The excess rate (2.35%) and the band limits (12,500 / 25,000 / 50,000 / 75,000) are shared. Record the figures in [hypotheekrenteaftrek-rules.md](hypotheekrenteaftrek-rules.md) as well.
   - `sources`: a source list and, if you checked the values against something specific, a `verified` note for each of `nl`, `mortgageDeductionRateCap`, `be` and `home`. Add a `url` only for a page you have actually used. Leave `verified` unset when the values were only taken from published tables; do not claim a check that did not happen.
3. **Register the year** with one import and one entry in `YEAR_MODULES` in `src/tax/years/index.ts`, in ascending order. `VALID_YEARS`, `TaxYear`, `TAX_PARAMS` and `EIGENWONINGFORFAIT` derive from it, and with them the schema, the year selector, the year comparison and `getCapabilities()`. TypeScript will then flag every record keyed by `TaxYear`.
4. **Run the parameter integrity tests** (`pnpm exec vitest run tests/tax/params.test.ts`). They check contiguous brackets, that the premium ceiling is the first bracket ceiling, that the arbeidskorting stages join up and reach zero, that the algemene heffingskorting phases out at the top bracket, and that every table and source exists. A failure usually means a mistyped figure. If a published table really is inconsistent, list it in `KNOWN_DEVIATIONS` in that test with the reason, rather than loosening the check.
5. **Update the snapshot only deliberately.** `tests/tax/fixtures/tax-params-snapshot.json` pins every figure of the existing years. Adding a year means adding that year's entries to it; changing an existing figure means correcting data, so say so in the changelog.
6. **Update year-specific text.** Messages that mention a year or a law change (for example the dienstencheques hints) live in `messages/en.json` and `messages/nl.json`; keep both locales in step (`pnpm check-message-parity`).
7. **Add tests** in `tests/tax/` for the new year: at least one bracket boundary on each side, credits at their phase-out points, the BE allowance with and without children, and the mortgage forfait. Update year lists in existing tests (`capabilities`, `strict`, `mortgage`) and the multi-year comparison test.
8. **Check against a real assessment if you can.** Compare income tax, premiums, credits, and the Belgian figures with an actual aanslag and record what matched in the verification table of [tax-model.md](tax-model.md), and in the module's `verified` note. Say so when a year is taken only from published tables.
9. **Run** `pnpm lint`, `pnpm typecheck`, `pnpm test` and `pnpm build` sequentially (Paraglide writes generated files), then update `CHANGELOG.md` under `[Unreleased]` and the supported-years statements in `README.md` and `tax-model.md`.

Income year 2026 was added this way once the official tables were published ([#144](https://github.com/tjorim/bordertax/issues/144)); `2026.ts` lists the page each table was taken from. Add the next year (2027) only after the same checks.
